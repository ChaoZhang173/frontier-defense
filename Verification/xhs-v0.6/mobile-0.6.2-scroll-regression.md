v0.6.2 横屏菜单滚动独立集成回归

用户真机反馈为：iPhone 横屏中文字/按钮上滑动只挪一点，空白处和正常竖屏流畅。另一审查通过旧源码复现：子元素隐式捕获转移给面板时，子元素的 lostpointercapture 冒泡至面板，被误认为面板自身失去捕获，从而在第一段移动后清除拖动。最小修复过滤事件 target，仅处理面板自身丢失捕获，保留正常竖屏原生滚动。

本审查另确认 app 并非每帧清除菜单手势：syncMode 在模式相同时提前返回。旧版本的同尺寸 resize 会取消拖动，可注入复现第一段后停止；当前版本忽略这种无尺寸变化的通知，真实尺寸变化仍取消旧坐标手势。

滚动集成 40/40 通过。实际 app 的科技标签页生成八张卡片，测试事件模型覆盖捕获/目标/冒泡三个阶段、触摸子元素隐式捕获、延迟捕获转移及子元素 lostpointercapture 冒泡；同时运行实际 app 帧回调。

- 文字、说明、按钮、卡片、空白五种起点，在顺/逆时针旋转时连续滑动 100、240、300 CSS 像素，再连续反向回到原点。
- 整页到达最大 scrollTop 后继续拖动 100 像素，反向第一段 10 像素立即生效，最终可回到顶部。
- 每段都注入同尺寸 resize，仍完整移动 300 像素且无 stop 调用；真实尺寸 resize 恰好取消一次。
- 500 段各 0.6 CSS 像素的移动及回拖没有逐段取整丢失。触摸坐标按浏览器 client CSS 像素处理，没有假设额外 CSS scale 变换。
- 正常横/竖屏事件未被 JS preventDefault，也未被 JS 修改 scrollTop，保留原生滚动。

输入回归 28/28，通过真实尺寸变化清输入及同尺寸通知保留控制；真实 Three 相机投影 108/108。

这些测试未使用浏览器或 iPhone。八卡数据由实际 renderTerminal 生成，但滚动容器高度由明示测试夹具提供；scrollTop/max 校验了数值边界，不能证明原生滚动条绘制或手机合成层表现。发布前后的真机文字区域长滑、到底回拖仍是体验验收。
