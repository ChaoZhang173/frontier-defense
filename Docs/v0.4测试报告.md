# v0.4 试玩验证报告

## 运行检查

实际运行 Mac 游戏，233 项检查全部通过。构建发布前最后一次代码变更是修正驻军绕墙时的障碍探测半径；下表检查均已在该修正后通过。

| squad | 32 | 通过 |

| afk | 3 | 通过 |
| defeat | 3 | 通过 |

完整五波自动玩家使用实际步枪、真实收入、小队与建筑升级，生成并消灭全部 308 个敌人。玩家击杀 216，小队击杀 12，阵亡 0 次，指挥中心剩余 2300 耐久，模拟 520.1 秒。这条回归沿用旧策略、未购买扩建和科技；新内容由专项独立验证，最终难度和建造时机仍需真人试玩评价。

无人操作在第 3 波约 238.7 秒失守；预先破坏防线模式在第 1 波约 43.8 秒失败。旧策略驻军最多 8，新机制专项确认 12 人上限。敌人总数和 55 个存活上限保留。

## 建造、科技与双地堡

108 项专项覆盖：建造费用、工期和占位拒绝；暂停中下单与恢复施工；工地不能攻击/生产、友军免伤、敌人实际索敌攻击；施工和竣工刷新小队路线；工地及四处正式建筑的毁坏重建；建筑升级继承、全体生效与单体维修。

双兵营拥有独立生产周期，共享 8 / 12 驻军上限。检查增援兵营损毁时保留现有士兵、暂停研究，重建后恢复生产与未完成研究；两项科技的费用、计时、队列、重复购买拒绝，以及所有对应单位的实际伤害变化均通过。

玩家驻东堡、小队驻西堡时，两侧同时实际射击命中。分别摧毁和重建两座地堡，只清理对应驻军绑定；另一侧仍继续受保护和驻守。原有射孔遮挡、射界、出入、跟随和重启重置检查保留。

专项最后重载场景，所以 construction / fortification / squad 报告摘要中的升级、人数和已建建筑为新对局状态；前置结果在 checks 中保留。

### 增援实际行军

从增援兵营真实补出左右岗位新兵，在无敌人的战场持续模拟 40 秒；逐帧检查不穿建筑，最终均在目标岗位 0.8 米内。首次新增检查发现旧探测半径小于驻军身体，造成绕墙时轻微穿入边缘；修正驻军的前进与侧移探测后，两条路线及所有战斗回归通过。
