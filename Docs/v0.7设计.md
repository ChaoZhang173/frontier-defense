# 边境防线 v0.7 设计

本轮在 Unity 版本上扩展基地防守与自动反攻，交付范围为 Mac 原生包和桌面网页包，包含 Web 托管包与 OfflineWeb 分享包。公开 Sites 站点保持旧版，小红书、Windows 和手机适配不属于本轮更新。

本文描述实现规则。构建、测试、截图和平台限制见 [v0.7 测试报告](v0.7测试报告.md)；这里不代替实际验证结论。

## 1. 战场与基地布局

地图范围为 X -60 至 60、Z -24 至 136，东西宽 120 米、纵深 160 米。基地仍位于南侧高地，东西入口对应两条主坡道。外场增加八处有实际碰撞的废墟掩体、两翼道路和纵深路线，玩家、小队、守军与突击队使用共享的地形与寻路规则。

两座我方地堡开局都已建成，位置分别为 (-20.5, 20) 和 (20.5, 20)，位于两个入口外侧。入口外侧正面围墙降至 0.6 米，中央墙维持 0.7 米，门柱改为低矮标识，保留身体阻挡，同时给地堡射孔与中央矮墙防线留出火力通道。后门入口、每堡五席、玩家和小队优先、逐人让位以及单堡独立撤离规则继续保留。

中央矮墙与坦克阵位继续使用原有防守规则；小队可在中央区域接收驻守命令。主兵营开局投产，增援兵营与战车工厂仍需建造。被毁建筑可以在自己的固定位置重建。

## 2. 六座敌方传送门基地

| 深度 | 西侧传送门 X / Z | 东侧传送门 X / Z | 布局 |
| --- | --- | --- | --- |
| 前线 | -27 / 82 | 27 / 82 | 传送门、兵巢、两座炮塔、本地守军 |
| 中部 | -44 / 104 | 44 / 104 | 同样的基地结构，更高的建筑耐久与塔楼火力 |
| 纵深 | -16 / 121 | 16 / 121 | 同样的基地结构，最坚固的防线 |

每个基地的传送门、兵巢和两座炮塔都是可攻击、可摧毁的独立建筑，而非装饰。塔楼会攻击接近的玩家方人员和机械单位；本地守军巡逻并迎击接近者，不沿进攻波次路线主动计入总部攻势。

- 每座基地初始有两名本地守军，最多补充至四名。
- 传送门与兵巢都存活时，当地守军才能补员。
- 摧毁传送门会取消该来源尚未出动的进攻队列及后续批次；已经出动的敌人继续作战。
- 摧毁传送门或兵巢会停止当地守军补员，已经存活的守军不会凭空消失。
- 摧毁炮塔只撤去该塔火力；传送门和兵巢仍各自遵循生存状态。
- 敌方建筑被摧毁后本局不重建。传送门、兵巢、炮塔的击毁奖励分别为 300、90、150 补给。

## 3. 敌军数量与角色

| 波次 | 计划出兵 |
| --- | ---: |
| 第一波 | 56 |
| 第二波 | 80 |
| 第三波 | 116 |
| 第四波 | 156 |
| 第五波 | 200 |
| 合计 | 608 |

计划总数用于记录完整攻势。玩家或突击队提前切断传送门时，对应未出动敌人会被取消，因此实际生成数量可能低于 608。被取消部分单独计数，不能让波次永久等待已经消失的来源。

五种移动敌人承担不同职责：迅行兽持续近身压迫，酸脊兽远程射击，铁甲兽承受伤害并冲击建筑，新增潜袭兽以更高速度接近目标，新增攻城兽在较远距离对建筑施压。第三波起加入更完整的重甲、远程与攻城混编。

同时存活的移动敌人上限为 100，包含波次进攻部队和基地守军；传送门、兵巢与炮塔不占移动敌人名额。达到上限时出兵队列等待空位，不因等待而一次性释放全部积压敌人。

第一至第四波在本波尚待出动数量与实际进攻敌人都清零后进入 45 秒自由整备，第五波完成后胜利。独立基地守军和敌方建筑不阻止波次结算。指挥中心被摧毁仍立即失败。

## 4. 我方独立集结与自动出征

突击兵使用独立生产计时和角色，不使用普通守卫岗位、玩家小队名额或战车工厂槽位。有存活的兵营时可以持续补员；增援兵营投产后加快突击兵生产。出兵口被占用时等待，不重叠生成单位。

| 编制 | 名额 | 控制方式 |
| --- | ---: | --- |
| 基地普通守卫 | 8；增援兵营投产后 12 | 防守岗位与自动驻堡 |
| 自动突击兵 | 24 | 集结、出征、目标转移、回防 |
| 玩家随行小队 | 4 | 两名雇佣兵与两名招募守卫，接受玩家命令 |
| 坦克 | 1 | 工厂生产，自动前往中央阵位 |
| 维修工 | 2 | 独立维护基地 |

突击兵从兵营出口实际走向基地内绿色集结区，六名成员都抵达自己的集结位置后组成一队出发。行军经过对应入口和坡道，向敌方传送门基地推进；遇到可攻击目标时进行实际射击，并承受敌方守军和炮塔攻击。

当前目标传送门被摧毁后，存活突击兵重新寻找仍存活的目标，无需返回基地重新集结。所有传送门被清除后停止生产，部队返回基地待命。兵营暂时失去生产能力时保留计时进度；暂停或打开指挥中心终端时，生产、集结与行军统一暂停。

生产由 `ExpeditionDirector` 的独立计时器控制，每 12 秒补充一人，增援兵营投产后缩短为 9 秒。步枪对建筑造成一半伤害，避免免费突击队过快独立拆完所有据点；对敌兵的火力保持不变。普通守卫仍使用原有岗位与补员规则。

## 5. 维修工

基地初始部署两名黄色维修工，不配备普通守卫的作战控制器，也不能作为随行守卫招募。工人有独立生命值，可以被敌人攻击；死亡后经过 20 秒有效游戏时间免费补充，暂停和终端不推进替换计时。

工人按损伤和路程选择目标，实际走到目标旁可到达的服务位置，并且需要清晰视线。维修速度为每人每秒 6 点耐久，持续维修不会超过目标当前的最大耐久。维修路径限制在基地内，不能隔墙、远程或向地图外场维修。

可维修目标必须同时满足：存活、友方、已经受损、位于基地内，并且为已完成建筑或带机械属性的单位。施工中的地基、已毁建筑、敌人、步兵和基地外单位都不接受维修。

当前可维修的机械战斗单位是坦克。机械标记为以后加入其他载具留出接口；本轮没有新增飞机、星港或空军生产。

## 6. 建筑加固替代购买回血

原有建筑维修购买项改为结构加固。每次购买同时增加最大耐久与当前耐久，增加值完全相同，因此不会抹掉购买前已经承受的伤害。例如地堡从 1,080 / 1,200 加固后变为 1,680 / 1,800，仍缺少 120 耐久，由工人逐渐维修。

| 建筑 | 每级新增最大耐久与当前耐久 | 第一 / 第二 / 第三级价格 |
| --- | ---: | --- |
| 指挥中心 | 650 | 120 / 240 / 360 |
| 主兵营、增援兵营 | 450 | 100 / 200 / 300 |
| 每座地堡 | 600 | 120 / 240 / 360 |
| 战车工厂 | 700 | 180 / 360 / 540 |

每个物理建造位置独立记录最多三级。满血建筑也可加固；施工中或已被摧毁的建筑不可购买加固，不能借此复活。重复操作、等级达到上限或补给不足时不扣费。

建筑被毁后，原建造位置保留已购加固等级。重建完成时，新建筑获得该位置的累计加固上限。原有全体地堡装甲升级仍然独立存在；重建地堡按基础耐久、全体装甲加成、该位置加固加成相加，不能遗漏或重复叠加。

加固、建造、研究、步枪强化、协同火力和雇佣兵合同都需要在指挥中心终端操作。日常建筑回血由工人自动完成。

## 7. 实现与交付对应

| 规则 | 主要实现 |
| --- | --- |
| 地图边界、坡道、外场掩体 | `GroundSurface`、`Art`、`EnemyFronts` |
| 敌方基地、守军、塔楼 | `EnemyDefenseDirector` |
| 五波攻势与来源取消 | `WavePlan`、`AssaultDirector`、`GameWorld` |
| 独立突击队 | `ExpeditionDirector`、`ExpeditionArt` |
| 工人寻路与维修 | `RepairDirector`、共享导航 |
| 每址加固与重建继承 | `ConstructionDirector`、`BaseUpgrades` |
| 指挥中心加固与界面 | `GameWorld`、`GameHud` |

Mac、Web 托管包与 OfflineWeb 分享包使用这一份 Unity 生产代码。它们的实际版本、包体与验证证据见 [v0.7 测试报告](v0.7测试报告.md)。历史 Sites 链接保留在 [README](../README.md)，本轮没有向该站点发布 v0.7；小红书包也不随本轮更新。
