# v0.6 小红书上传与手机适配评估

评估日期：2026-09-16。评估对象为现有《边境防线》v0.6，未更换游戏，未修改运行代码，未重新构建。本文件记录项目只读审查结果，以及本轮主任务在小红书创作后台核实的上传前提。

## 当前结论

现有 Unity v0.6 包不能直接作为小红书小工具上传运行。当前官方能力清单仍禁用 WebAssembly，而现有网页包、Sites 在线版和单文件 OfflineWeb 版都依赖 WebAssembly。改变扩展名、重新压 ZIP 或把资源内嵌到 HTML，均不能消除该依赖。

本轮已在登录后的电脑创作后台点击上传入口；账号当前还要求在小红书 App 扫码完成实名认证。实名认证必须由账号本人完成。此要求与运行时兼容限制是两个独立条件：完成实名也不会使现有 Unity 包自动变得兼容。

官方参考：[小工具操作指南](https://fe.xiaohongshu.com/ditto/vincent/0df3caa3417d4c008b2c06689cf1653a?fullscreen=true&naviHidden=yes&source=wowcard)、[小工具能力清单](https://fe-video-qc.xhscdn.com/fe-platform-file/104101b8323q4m0uaga06277180ac7t8006ptl0e12ek1g)。平台要求可能调整，正式打包前应以账号后台最新提示和官方文档为准。

## 路径一：为小红书移植同款核心玩法

这是满足“朋友在小红书内直接点开玩”的路径，但属于移植开发，不是上传格式转换。本轮用户已选择制作保留核心玩法的小红书兼容版；不能静默替换成另一个小游戏，也不能把缩减后的实现称为原 Unity v0.6 完整版。

应以 `Docs/v0.6设计.md` 为规则来源，保留双方确认的核心玩法：两路基地防守、第三人称移动和射击、五波敌潮、指挥中心经营、地堡、小队、战车工厂与自动坦克、中央防线及敌巢炮塔。若设备性能或平台 API 迫使画面、人数或机制简化，需要明确列出差异并确认范围。

实现必须符合小工具允许的纯网页运行环境：不使用 WASM，不依赖在线接口，图片、字体、脚本等资源随包提供。正式选型前还须核实平台对 WebGL、Canvas、音频、存储、文件类型、压缩包大小及横竖屏的当前支持，不能仅因普通浏览器能运行就认定小红书可运行。

触屏交互应在移植时作为基础设计：左侧摇杆移动，右侧空白区域拖动视角，射击/瞄准/换弹/交互按钮，小队命令与暂停入口；菜单切换及失焦必须释放所有按住状态。优先横屏游戏布局，同时提供竖屏时清晰的横屏引导，并以小红书真机预览结果决定是否需要竖屏布局。

完成顺序：确认移植范围 → 制作同款可玩原型与手机界面 → 本地校验离线资源 → 后台上传 → 小红书手机扫码预览 → 修复兼容问题 → 提交审核。原版数值与批次调度已另行摘录至 `Verification/xhs-v0.6/reference-rules.json`；本评估文档本身不作为移植、上传或审核完成的证明。

## 路径二：在原 Unity v0.6 上适配手机浏览器

这条路径保留现有代码与内容，并通过浏览器链接免安装试玩。它仍使用 WASM，不能解决当前小红书小工具的兼容限制；分享网页也不能保证小红书笔记允许直接跳转该链接。已有 Sites 地址在中国大陆部分网络无法打开，访问可达性仍需要单独验证。

必要改动如下。

### 1. 统一键鼠与触摸输入

- `UnityProject/Assets/Scripts/PlayerMotor.cs:28` 的 `LostControl`、`:53` 的输入门槛、`:228` 的 `RequestControl` 都依赖鼠标锁定。触控模式必须绕过鼠标锁定条件，同时保留桌面鼠标失控保护。
- `PlayerMotor.cs:54`–`:81` 需要接入移动向量、视角增量、持续射击/瞄准/冲刺与单次换弹/命令。保留现有移动、射击、瞄准、地堡射界和战斗计算，不用模拟键盘事件替代输入层。
- `UnityProject/Assets/Scripts/GameWorld.cs:246`–`:251` 需要把暂停与 E 交互映射到触屏按钮，避免触屏没有鼠标锁定导致进入游戏 0.8 秒后自动暂停。
- 使用独立触点标识处理多点触控，允许同时移动、转动视角和射击；每个触点从开始到结束只属于一个控制区域。按钮区域不能同时驱动视角，菜单触摸不能穿透成射击。
- `GameWorld.Interact()` 已集中处理招募、进出地堡和指挥中心（`:426`–`:436`），手机交互按钮应复用该方法；F/G/B 分别复用既有小队跟随、驻守和入堡操作。
- 在暂停、打开终端、返回首页、阵亡、窗口失焦、触点取消时清空持续状态，防止卡住移动或持续开火。

### 2. 重排手机 HUD 与菜单

- `UnityProject/Assets/Scripts/GameHud.cs:22` 以 1440 × 900 设计基准缩放；手机横屏会把字号与按钮按比例缩得过小。不能只把整套桌面 HUD 缩到手机上。
- `GameHud.cs:67` 起的战斗 HUD 同时包含血量、波次、小地图、小队、地堡、坦克和工程卡片。手机应保留核心读数，其他信息用可展开面板承载，为左右拇指留出操作区，并避开准星和交互提示。
- `GameHud.cs:529` 起的指挥终端为固定 1120 × 728 布局；建造/科技按钮有高度仅 24 个设计单位的项目。手机需更大触摸目标，可滚动或分组呈现，所有升级、雇佣、维修和研究仍需可达。
- `GameHud.cs:48` 的任务简报、`:411` 的设置、`:431` 的结算页均需手机版布局和触摸说明。设置中的“鼠标灵敏度”应区分触屏视角灵敏度；暂停文案不能再要求“恢复鼠标控制”。
- 新增中文文本后，应运行 `Tools/update_font.py` 更新现有精简字体，避免手机按钮出现缺字。

### 3. 网页容器与设备表现

- `UnityProject/Assets/WebGLTemplates/Frontier/index.html` 当前只对页脚做简单窄屏处理，仍显示“电脑浏览器试玩”。需要 `viewport-fit=cover`、安全区留白、触摸手势控制、横竖屏切换、动态视口尺寸及手机加载提示。
- 不应依赖强制全屏或强制横屏才能操作；小红书内嵌页面和手机浏览器对相关 API 的支持须实测。网页控制区域需防止页面滚动、缩放和长按菜单干扰游戏，并保留必要的可访问入口。
- `GameWorld.cs:117` 的质量设置和 WebGL 模板中的像素比上限可作为性能调节入口。当前默认均衡画质、软阴影、60 FPS，WebGL 初始内存为 256 MiB、最大 2048 MiB（`FrontierBuild.cs:60`）；这些数值不代表手机实际内存占用，但意味着必须真机检查启动峰值和长时间对局稳定性。
- 性能调整优先降低渲染分辨率、阴影和特效成本，不能为了手机帧率无说明地删除敌人、波次或核心 v0.6 机制。

## 必要验证与交付边界

手机验证至少应覆盖：左右手同时操作、按住射击并转向、瞄准和换弹、三类 E 交互、F/G/B 小队命令、进入/退出地堡后的视角限制、三页指挥终端与所有购买入口、暂停恢复、切后台恢复、阵亡重生、横竖屏切换、第五波高负载和完整对局。

桌面还须回归键鼠移动/射击、Esc 与鼠标恢复、指挥中心暂停、地堡交互等受输入改动影响的行为。已有 v0.6 的 583 项 Mac 检查不能当成触屏或小红书兼容性证明，触控仿真也不能代替 iOS/Android 内嵌页面真机验证。

本次成果是兼容性评估。现有 v0.6 发布包和 Sites 站点均未改动；未生成可提交的小红书包，未宣称完成手机适配或上传。
